# OCR local
#
# pytesseract es solo el ENVOLTORIO de Python: ademas hace falta el binario del
# sistema, que no se instala con pip.
#
#   macOS:    brew install tesseract tesseract-lang
#   Debian:   apt-get install tesseract-ocr tesseract-ocr-spa
#
# El Dockerfile lo instala. Sin el binario, `OCR_ENABLED=true` no falla al
# arrancar: falla por cada foto, y el operador ve "fallo de OCR" en lugar de
# "no instalaste tesseract". `GET /api/v1/scan/ocr` dice cual de los dos falta.
# pytesseract devuelve arrays de numpy y los convierte con `image_to_data`.
# Llega arrastrado por pandas y torch, pero se declara porque ahora el codigo de
# captura lo necesita de forma directa.

# easyocr: el SEGUNDO motor de OCR, apagado por omision.
#
# Tesseract es el que corre por omision y el que da el 98.5% sobre PDF. Sobre
# fotos el medido es 33.3% (`AGENTS.md`), y easyocr esta ahi para contrastar los
# dos motores antes de aceptar que 33.3% es el piso. Se mide con
# `scripts/medir_dos_motores.py` y `scripts/diagnostico_easyocr.py`.
#
# `torchvision` NO se declara aqui aunque easyocr la pida, y esa es la parte
# importante: se instala en el Dockerfile, desde el indice CPU, junto a torch.
# torchvision fija una version exacta de torch; si llegara por este archivo pip
# la resolveria desde PyPI, cuya build de torch trae CUDA, y reinstalaria torch
# encima de la version CPU. Ver el comentario del Dockerfile.
easyocr>=1.7.2

# OpenCV: el umbral ADAPTATIVO del OCR. Opcional y degradado.
#
# `opencv-python-headless` y NO `opencv-python`: el primero no necesita `libGL`,
# y el `Dockerfile` documenta que en `python:3.11-slim` `libgl1` NO esta instalado
# a proposito. Con el flavor con ventana, `import cv2` revienta con
# `libGL.so.1: cannot open shared object file`, y parece un bug de OpenCV cuando
# es un paquete equivocado.
#
# Que sea OPCIONAL no es una cortesia: `ocr.py:_binarizar` devuelve `None` sin
# el, y la lectura sigue siendo la de siempre. La etapa compite con la lectura
# normal en `_puntuar` y solo gana si el documento sale mejor leido, asi que no
# puede empeorar lo que ya funciona. `GET /api/v1/scan/ocr` dice si esta.
#
# Lo que NO se ha medido: si la binarizacion sube la exactitud. `docs/known-issues.md`
# §21 descarta el preprocesado con medicion, pero solo midio UMBRALES GLOBALES y
# filtros de nitidez; el adaptativo es otra pregunta y no esta medida todavia.
# Se mide con `scripts/medir_precision_ocr.py` cuando haya `verdad.json`.
